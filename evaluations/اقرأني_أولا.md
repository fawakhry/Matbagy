# اقرأني أولًا — برنامج تقييمات مطبعجي

**الحالة:** تعليمات التشغيل اليدوي وذاكرة المشروع متاحة على GitHub للقراءة في أي شات. **لم يُنشأ بعد مستودع GitHub خاص بالتقييمات، ولم يُرفع إليه برنامج V4، ولم تُنشأ قاعدة بيانات/Worker للتقييمات في Cloudflare، ولم يُربط TrendOS.** ملفات الكود والكتيب V4 سُلّمت داخل محادثة سابقة كحزمة محلية؛ لا تفترض أنها مثبتة على GitHub أو متاحة في شات جديد قبل التحقق.

## 1) بروتوكول افتتاح أي شات جديد

عندما يكتب المالك «جت هب برنامج التقييمات»، **لا تطلب منه إعادة شرح الخطة**. افتح هذا الملف **كاملًا**، ثم [سير العمل اليدوي](سير_العمل_اليدوي.md)، ثم [حالة المشروع](سجل_الحالة.md)، ثم [قالب البصمة](قالب_بصمة_العميل.md)، ثم [البنية المستهدفة](خطة_البنية_التحتية.md). اعمل من حالة GitHub الحالية، لا من انطباع عن آخر شات. لو لم تتمكن من قراءة الملفات، قل ذلك ولا تدّع أنك تعرف آخر تحديث.

إذا رفع ملف محادثة مع الأمر نفسه: اقرأ الخطة أولًا، ثم عالج الملف وفق بروتوكول استقبال محادثة جديدة. إذا قال «حدّث [العميل]» أو «شوف المشكلة [العميل]»: استدعِ البصمة الفعلية **من مخزن خاص موثق** قبل الاستنتاج. إذا لم يوجد مخزن خاص أو لا يمكن التحقق من أحدث بصمة، فلا تخترعها من الذاكرة؛ حلّل المتاح فقط، وميّز النتيجة بأنها غير مدموجة مع البصمة السابقة.

## 2) الهدف المتفق عليه

هذا ليس بوت ردود عام ولا نظام تقييم عقابي. المشروع يجمع محادثات الخاص ومجموعات الشغل المصرح باستخدامها، لبناء **بصمة تعامل متجددة لكل عميل** و**ملف أداء مهني لكل موظف**، وفهم تفاعل العميل والموظف ومسار الأوردر؛ ثم استخراج الرد المناسب، ومواطن الخلل، وأوامر متابعة قابلة للمراجعة. كل استنتاج قابل للنقض ويعود إلى رسالة مؤرخة؛ لا أحكام على الشخصية أو النوايا، ولا تقييم من واقعة منفردة.

بصمة العميل تشمل: تفضيلات التواصل المثبتة؛ المنتجات/المواصفات المعتادة؛ ما يزعجه في الخدمة والشكاوى المتكررة؛ أساليب المعالجة التي نجحت؛ سياسة المواعيد والوعود؛ سياق الأوردر الحالي؛ أمور تحتاج تأكيدًا. فصل تفضيل صرّح به العميل عن ملاحظة نمطية أو استنتاج غير مؤكد. لا تحول صفة «مقرف» إلى تشخيص؛ حوّلها إلى سلوك تشغيلي موثّق وإجراء تعامل.

ملف الموظف يشمل الالتزام بتسجيل المواصفات، دقة الوعود والمتابعة، التسليم بين الأقسام، الاستجابة للشكاوى، ظروف المسؤولية، ونقاط القوة والتدريب. لا تنسب التأخير تلقائيًا إلى الشخص الظاهر في آخر رسالة؛ تحقق من المسؤولية والتبعيات والمكالمات/الإجراءات غير المرئية. لا عقوبة آلية.

## 3) دورة العمل الآن — يدويًا داخل الشات

1. المالك يرفع ملف تصدير محادثة واتساب خاص أو مجموعة، ويكتب «جت هب برنامج التقييمات» أو «حلّل العميل». استخرج نوع المصدر، المشاركين، الأوقات، الرسائل، المرفقات المتاحة، ومؤشرات ربط الأوردر. لا تفترض أن ملفات الوسائط غير المرفقة قد شوهدت.
2. تحقق من الهوية ومنع تكرار الرسائل عبر مصدر+وقت+مرسل+محتوى/هوية رسالة إن أمكن. لا تدمج شخصين أو أوردرين بلا دليل.
3. استخرج وقائع محددة مع رقم/مرجع دليل وتاريخ: طلب، مواصفات، عرض سعر، وعد، اعتماد، تعديل، انتظار، شكوى، رد، تسليم/إلغاء. ميّز المطلوب عن المتفق عليه وعن المنفذ فعلًا.
4. استخرج **بصمة العميل** و**ملاحظات الموظفين** و**العلاقة بينهما** منفصلة؛ صنّف كل معلومة: تصريح مباشر/نمط موثق/استنتاج محتمل/غير محسوم.
5. اقترح تعليمات مخاطبة عملية للعميل، ومسودة رد **غير مُرسلة**، وإجراء متابعة بمسؤول ودليل وشرط اعتماده؛ لا تختلق سعرًا، وعد تسليم، خصمًا أو حالة أوردر.
6. اعرض النتيجة للمراجعة. لا تستعمل الملاحظات الحساسة أو الأحكام على الأشخاص كتعليمات آلية قبل اعتماد الإدارة.
7. إذا توفّر مستودع/مخزن **خاص** مصرح، اقرأ آخر نسخة بالمعرّف الثابت، أضف الجديد مع سجل تغييرات ورقم نسخة ودليل، اكتب إلى الوجهة الخاصة، **ثم أعد قراءتها للتحقق من الحفظ**. إذا تعذر الحفظ: اذكر بوضوح «التحليل جاهز لكن البصمة لم تُحفظ في GitHub/المخزن» وقدّم ملفًا قابلًا للتسليم؛ لا تدّع الاستدعاء التلقائي في الشات الجديد.
8. إذا قال المالك «شوف المشكلة»، استدعِ آخر بصمة **المثبتة والمتاحة**، وقارنها بمحادثات الحالة الحالية، واعرض الوقائع والتفسيرات البديلة والرد المقترح والإجراء وحدود اليقين.

## 4) حدود الخصوصية والكتابة

هذا المسار `fawakhry/Matbagy/evaluations/` **عام** ويحتوي السياسات والقوالب وحالة التنفيذ العامة فقط. **لا أسماء/أرقام/ملفات/صوتيات/صور/تفاصيل طلبات حقيقية، ولا بصمات فردية أو API keys هنا**، حتى لو كان العميل معروفًا سابقًا. ملفات العملاء الأصلية والهوية وربط البيانات تُنقل لاحقًا إلى تخزين خاص؛ لا تحول ملف GitHub عام إلى سجل عملاء. لا تضع بيانات خاصة في Git commits أو Issues أو Actions logs.

كل إعادة تحليل للمحادثات تتم بطلب المالك وبصلاحية استخدام البيانات. لا ترسل محتوى لجهة AI خارجية دون توضيح/موافقة مناسبة؛ حالياً أي استدعاء API من البرنامج منفصل عن تحليل المساعد داخل الشات.

## 5) التدرج المعتمد

**الآن:** تحليل يدوي داخل أي شات، توليد/تحديث بصمة بمراجعة وحفظ خاص مؤكد عند توفره. **لاحقًا:** نشر واجهة مستقلة للتقييمات وربط قاعدة بيانات خاصة وR2 وOpenAI API، ثم استقبال رسائل جديد مصرح به، ثم ردود شبه أوتوماتيكية مع اعتماد الالتزامات. **أخيرًا فقط:** ربط محدود بـTrendOS يبدأ بالقراءة؛ لا تعديل موارده أو Cloudflare Worker أو D1 الخاصة به تحت هذا المسار.

ارجع إلى [سجل الحالة](سجل_الحالة.md) لمعرفة ما تم فعليًا وما بقي، ولا تحول خطة إلى حالة تشغيل منشورة.
