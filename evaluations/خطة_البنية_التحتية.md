# بنية برنامج التقييمات — الفعلي مقابل المستهدف

## ما هو موجود فعلًا الآن
- إجراءات التشغيل اليدوي مُسجَّلة في هذا المسار العام `fawakhry/Matbagy/evaluations/`.
- حزمة برنامج تجريبي V4 وكتيّب تشغيل صُنعا وسُلّما داخل محادثة سابقة **ولم يُرفعا من هذا المسار إلى GitHub**. لا تستنتج صلاحية نسخة GitHub أو حالة Cloudflare من وجود الكتيّب المحلي.
- لم يُنشأ مستودع تقييمات خاص، ولا تخزين بصمات خاص متصل بالشاتات، ولا ربط API أو واتساب أو TrendOS، وفق آخر فحص مسجل هنا.

## البنية المستهدفة بالتسلسل

```text
GitHub PRIVATE repository: program source, instructions, tests; optional redacted operational profiles only with owner policy
                  │ CI/build (without private chat data)
                  ▼
Cloudflare Worker for evaluations (NEW isolated project, not TrendOS Worker)
    ├─ auth + roles + audit + approval gates
    ├─ new independent D1: customer IDs, evidence pointers, profile versions, review/action state
    ├─ new private R2: original chat exports, audio/images, optional encrypted profile source
    └─ server-only OpenAI API key: opt-in analysis, bounded context and costs
                  │
           dashboard and human approval
                  ▼
TrendOS integration: LAST phase, initially read-only, separately approved
```

خيار آخر للمخزن الخاص اليدوي قبل نشر السحابة: مستودع GitHub **خاص جديد** تُحفظ فيه بصمات تشغيلية موجزة ومراجع الأدلة، من غير نسخ محادثات خام أو كلمات مرور. قبل أول ملف عميل: تحقق أن المستودع PRIVATE وقصر صلاحيات الوصول وسجّل معرّف العميل ورقم النسخة ونتيجة read-back. مستودع Matbagy الحالي PUBLIC ولا يصلح مطلقًا لهذا الغرض.

## خطوات لم تتم بعد
1. تجهيز مستودع مستقل خاص: مثل `fawakhry/Matbagy-Evaluations`، مع ضبط الصلاحيات ورفع كود V4 بعد مراجعة الأسرار والتبعيات؛ **هذا اسم مستهدف غير منشأ**.
2. إنشاء Cloudflare D1 وR2 وWorker مستقلين بعد جرد ما هو موجود في حساب المالك وتحديد حدود التكلفة/الحصة؛ لا تمس `trendos-main` أو bindings/Workers الإنتاجية.
3. تفعيل مصادقة وصول وصلاحيات وتحكم في الموافقات وتشفير/سياسة الاحتفاظ والنسخ الاحتياطي قبل رفع بيانات حقيقية.
4. اختبار نهاية-لنهاية بملفات مصرح بها، اختبار الـdedupe ودقة البصمة، وقياس التكلفة وقراءة أحدث إصدار بعد انقطاع الشات.
5. السماح بالإرسال/الأوامر شبه الآلية تدريجيًا بعد الاعتماد. عدم إرسال واتساب أو تنفيذ أوامر TrendOS حاليًا.
